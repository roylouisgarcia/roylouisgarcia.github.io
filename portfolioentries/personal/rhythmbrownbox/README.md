# RhythmBrownBox

A browser step-sequencer / drum machine, kept here as a three-stage evolution of
the same project.

**Start at [`index.html`](index.html)** — the hub links every version's demo and
documentation, and the doc pages cross-link to each other and back to their demo.

| Version | Demo | Documentation | State |
|---|---|---|---|
| v1 | [`ver_1/index.html`](ver_1/index.html) | [page](ver_1/documentation/index.html) · [md](ver_1/documentation/summary.md) | original build — NexusUI + Bootstrap, no tooling — preserved as-is |
| v2 | [`ver_2/index.html`](ver_2/index.html) | [page](ver_2/documentation/index.html) · [md](ver_2/documentation/summary.md) | 2026 rebuild — no dependencies, unit-tested, keyboard + screen-reader accessible |
| v3 | — | [page](ver_3/documentation/index.html) · [md](ver_3/documentation/summary.md) · [plan 1–4](ver_3/documentation/plan-1-spec.md) | in design — spec set; 4-part write-up plans it four ways (TDD/BDD/FDD/DDD), building FDD |

Each `ver_N/index.html` is a single self-contained file: every script, style,
sample and image is inlined, so it runs with no server and no build step.

`documentation/summary.md` is the source of each write-up; `documentation/index.html`
is that same content rendered with navigation. v3 also carries a four-part build
plan as `ver_3/documentation/plan-*.md`, rendered the same way with a series pager.
The doc pages, the plan series, the hub, and both packaged demos are regenerated by
`documentation/rhythmbrownbox-build/build_portfolio.py`
at the repo root (a private, non-deployed working script) &mdash; re-run it after
editing any `summary.md` or after a new v2 single-file build.

The working source trees live outside this portfolio and are **not** vendored as
git submodules — these folders are packaged snapshots.
